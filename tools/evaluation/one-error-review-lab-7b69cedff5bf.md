## What the 37 cases say

- **20 producer-field errors.** Many are not simple unreadable-label failures: visible one-word/short brand names are omitted (#17, #31, #43, #97, #104, #114, #118, #141, #146), while others show near-character confusions (#18, #45, #75, #136) or confusion between producer and classification/legal text (#62, #69, #159). Repeated products (#12/#117, #42/#61, #17/#141, #46/#122, #55/#168, #62/#69, #44/#85) help isolate repeatable patterns.
- **12 wine-name errors.** Several are role/selection failures rather than unreadable words: visible appellations are already recognized but not copied into the expected wine-name field (#46/#94/#122/#167); visible names lose to appellation/classification/legal text (#48/#55/#60/#133/#157); and a plainly legible name is left blank (#135). #63 is adjudicated separately as described above.
- **3 subregion fills (#59/#72/#93).** Lab reads “Bordeaux Supérieur” correctly. The benchmark expects a blank subregion because the value is treated as the wine-name/appellation, so these are field-policy disagreements, not OCR-reading errors. Expected blanks remain valid; do not turn them into generic failures.
- **2 missing regions (#44/#85).** The label says Pays d’Oc; the imported reference uses parent region Languedoc-Roussillon. Lab does not map the IGP to that broader parent. Keep benchmark correctness separate from runtime gates and preserve the fact the broader value is inferred, not visibly printed.

The three Bordeaux Supérieur cases and two Pays d’Oc cases are the clearest examples where the benchmark schema/normalization affects the error label. They should be discussed separately from failures to recognize text. No other imported reference was changed during this visual review; #63 remains the only user-confirmed adjudication.
